# ISO 27001 — Information Security Management System (ISMS)

> ISO 27001 is the global standard for information security.
> Every bank, hospital, payment processor, and cloud company uses it.
> As a DevOps engineer, you implement the technical controls that make ISO 27001 real.

---

## What Is ISO 27001?

```
ISO 27001 = A framework for managing information security risks

It does NOT tell you WHICH technology to use.
It tells you WHAT controls you must have.

YOU decide HOW to implement them → with Terraform, Kubernetes, CI/CD, etc.

Structure:
  - Clauses 4-10: Management requirements (policies, audits, reviews)
  - Annex A: 93 security controls organized in 4 themes
    * Organizational controls (37)
    * People controls (8)
    * Physical controls (14)
    * Technological controls (34)  ← DevOps implements these
```

### 8.2 — Privileged Access Rights

**What ISO 27001 requires:**
- Only authorized people have admin access
- Privileged access is reviewed regularly
- Principle of least privilege

**How DevOps implements it:**

```hcl
# terraform/iam-least-privilege.tf

# BAD: Admin access to everyone
resource "aws_iam_group_policy_attachment" "bad" {
  group      = "developers"
  policy_arn = "arn:aws:iam::aws:policy/AdministratorAccess"  # NEVER DO THIS
}

# GOOD: Least privilege per team
resource "aws_iam_policy" "developer_policy" {
  name = "DeveloperLeastPrivilege"
  
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "ReadOwnResources"
        Effect = "Allow"
        Action = [
          "ec2:Describe*",
          "ecs:Describe*",
          "logs:Describe*",
          "logs:Get*",
          "s3:GetObject",
          "s3:ListBucket"
        ]
        Resource = "*"
        Condition = {
          StringEquals = {
            "aws:ResourceTag/Team" = "development"
          }
        }
      },
      {
        Sid    = "DenyPrivilegedActions"
        Effect = "Deny"
        Action = [
          "iam:*",
          "organizations:*",
          "account:*",
          "kms:DeleteKey",
          "kms:ScheduleKeyDeletion"
        ]
        Resource = "*"
      }
    ]
  })
}

# Privileged access review automation
resource "aws_config_config_rule" "iam_root_access_key" {
  name = "iam-root-access-key-check"
  source {
    owner             = "AWS"
    source_identifier = "IAM_ROOT_ACCESS_KEY_CHECK"
  }
}
```

```bash
# scripts/privileged-access-review.sh
# Run monthly — audit who has admin access (ISO 27001 A.8.2)

echo "=== Privileged Access Review - $(date) ==="
echo "ISO 27001 Control: 8.2 Privileged Access Rights"
echo ""

echo "--- IAM Users with AdministratorAccess ---"
aws iam list-users --query 'Users[*].UserName' --output text | \
  tr '\t' '\n' | while read user; do
    policies=$(aws iam list-attached-user-policies \
      --user-name "$user" \
      --query 'AttachedPolicies[?PolicyName==`AdministratorAccess`].PolicyName' \
      --output text)
    if [ -n "$policies" ]; then
      echo "  ADMIN USER: $user"
      # Get last activity
      aws iam get-user --user-name "$user" \
        --query 'User.{User:UserName,LastUsed:PasswordLastUsed}' \
        --output table
    fi
  done

echo ""
echo "--- Roles with AdministratorAccess ---"
aws iam list-roles --query 'Roles[*].RoleName' --output text | \
  tr '\t' '\n' | while read role; do
    policies=$(aws iam list-attached-role-policies \
      --role-name "$role" \
      --query 'AttachedPolicies[?PolicyName==`AdministratorAccess`].PolicyName' \
      --output text)
    if [ -n "$policies" ]; then
      echo "  ADMIN ROLE: $role"
    fi
  done

echo ""
echo "--- Root Account Usage (last 90 days) ---"
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=Username,AttributeValue=root \
  --start-time $(date -d '-90 days' +%Y-%m-%dT%H:%M:%S) \
  --query 'Events[*].{Time:EventTime,Event:EventName}' \
  --output table

echo ""
echo "Report saved: privileged-access-review-$(date +%Y%m).txt"
```

### 8.5 — Secure Authentication

**What ISO 27001 requires:**
- Multi-factor authentication (MFA) for privileged access
- Strong password policies
- No shared credentials

**How DevOps implements it:**

```bash
# Enforce MFA for all IAM users (cannot do anything without MFA)
# This policy goes on ALL users as a permissions boundary

cat > /tmp/mfa-enforcement-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowViewAccountInfo",
      "Effect": "Allow",
      "Action": [
        "iam:GetAccountPasswordPolicy",
        "iam:ListVirtualMFADevices"
      ],
      "Resource": "*"
    },
    {
      "Sid": "AllowManageOwnMFA",
      "Effect": "Allow",
      "Action": [
        "iam:CreateVirtualMFADevice",
        "iam:EnableMFADevice",
        "iam:GetUser",
        "iam:ListMFADevices"
      ],
      "Resource": [
        "arn:aws:iam::*:mfa/${aws:username}",
        "arn:aws:iam::*:user/${aws:username}"
      ]
    },
    {
      "Sid": "DenyAllExceptMFASetupWithoutMFA",
      "Effect": "Deny",
      "NotAction": [
        "iam:CreateVirtualMFADevice",
        "iam:EnableMFADevice",
        "iam:GetUser",
        "iam:ListMFADevices",
        "iam:ListVirtualMFADevices",
        "iam:ResyncMFADevice",
        "sts:GetSessionToken"
      ],
      "Resource": "*",
      "Condition": {
        "BoolIfExists": {
          "aws:MultiFactorAuthPresent": "false"
        }
      }
    }
  ]
}
EOF

# Create and attach to all users group
aws iam create-policy \
  --policy-name RequireMFAPolicy \
  --policy-document file:///tmp/mfa-enforcement-policy.json

aws iam attach-group-policy \
  --group-name AllUsers \
  --policy-arn arn:aws:iam::$(aws sts get-caller-identity --query Account --output text):policy/RequireMFAPolicy
```

### 8.8 — Management of Technical Vulnerabilities

**What ISO 27001 requires:**
- Know what vulnerabilities exist in your systems
- Fix them within defined timeframes (SLA)
- Track and report vulnerability status

**How DevOps implements it (in CI/CD):**

```yaml
# .github/workflows/vulnerability-management.yml
# ISO 27001 Control 8.8 — Technical Vulnerability Management

name: Security Scan — ISO 27001 Compliance

on:
  push:
    branches: [main, develop]
  schedule:
    - cron: '0 6 * * 1'  # Every Monday 6am — weekly scan

jobs:
  container-scan:
    name: Container Vulnerability Scan (Trivy)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build image
        run: docker build -t myapp:${{ github.sha }} .

      - name: Scan with Trivy (CRITICAL and HIGH)
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: myapp:${{ github.sha }}
          format: sarif
          output: trivy-results.sarif
          severity: CRITICAL,HIGH
          exit-code: 1  # FAIL the pipeline on critical vulnerabilities

      - name: Upload SARIF (ISO 27001 evidence)
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-results.sarif

  infrastructure-scan:
    name: Infrastructure Vulnerability Scan (Checkov)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Scan Terraform with Checkov
        uses: bridgecrewio/checkov-action@master
        with:
          directory: terraform/
          framework: terraform
          output_format: sarif
          output_file_path: checkov-results.sarif
          # ISO 27001 specific checks:
          check: |
            CKV_AWS_3    # EBS encryption
            CKV_AWS_19   # S3 encryption
            CKV_AWS_66   # CloudWatch log encryption
            CKV_AWS_119  # DynamoDB encryption
            CKV_AWS_144  # S3 cross-region replication
            CKV2_AWS_5   # Security Group not attached

      - name: Upload Checkov results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: checkov-results.sarif

  dependency-scan:
    name: Dependency Vulnerability Scan
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Scan with OWASP Dependency Check
        uses: dependency-check/Dependency-Check_Action@main
        with:
          project: 'MyApp'
          path: '.'
          format: 'HTML'
          args: >
            --enableRetired
            --failOnCVSS 7
            --suppression suppression.xml

      - name: Archive vulnerability report (audit evidence)
        uses: actions/upload-artifact@v4
        with:
          name: vulnerability-report-${{ github.run_number }}
          path: reports/
          retention-days: 365  # Keep 1 year for ISO 27001 audit

  vulnerability-sla-check:
    name: Check Vulnerability SLA Compliance
    runs-on: ubuntu-latest
    steps:
      - name: Check open critical vulnerabilities
        run: |
          # SLA: Critical = fix within 24 hours, High = 7 days, Medium = 30 days
          CRITICAL_COUNT=$(trivy image myapp:latest --severity CRITICAL --format json | \
            jq '.Results[].Vulnerabilities | length // 0' | paste -sd+ | bc)
          
          if [ "$CRITICAL_COUNT" -gt 0 ]; then
            echo "❌ ISO 27001 VIOLATION: $CRITICAL_COUNT critical vulnerabilities"
            echo "SLA: Critical vulnerabilities must be fixed within 24 hours"
            exit 1
          fi
          echo "✅ No critical vulnerabilities — ISO 27001 compliant"
```

### 8.15 — Logging

**What ISO 27001 requires:**
- Log all security-relevant events
- Protect logs from tampering
- Retain logs for a defined period
- Review logs regularly

**How DevOps implements it:**

```python
# ISO 27001 compliant audit logging
# Every security event must be logged with: WHO, WHAT, WHEN, WHERE, RESULT

import json
import logging
import time
from datetime import datetime, timezone
from functools import wraps

class ISO27001AuditLogger:
    """
    Structured audit logger for ISO 27001 compliance.
    Logs: WHO, WHAT, WHEN, WHERE, FROM_WHERE, RESULT
    """
    
    def __init__(self, service_name: str):
        self.service = service_name
        self.logger = logging.getLogger(f"audit.{service_name}")
        handler = logging.StreamHandler()
        handler.setFormatter(logging.Formatter('%(message)s'))
        self.logger.addHandler(handler)
        self.logger.setLevel(logging.INFO)
    
    def log_event(
        self,
        event_type: str,
        user_id: str,
        resource: str,
        action: str,
        result: str,  # "SUCCESS" | "FAILURE" | "DENIED"
        source_ip: str = None,
        details: dict = None
    ):
        event = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "iso27001_control": "8.15",
            "service": self.service,
            "event_type": event_type,
            "user_id": user_id,           # WHO
            "action": action,             # WHAT
            "resource": resource,         # WHERE
            "source_ip": source_ip,       # FROM WHERE
            "result": result,             # RESULT
            "details": details or {}
        }
        
        # Log at appropriate level
        if result == "FAILURE" or result == "DENIED":
            self.logger.warning(json.dumps(event))
        else:
            self.logger.info(json.dumps(event))
        
        return event
    
    def audit(self, event_type: str, resource: str, action: str):
        """Decorator for automatic audit logging"""
        def decorator(func):
            @wraps(func)
            def wrapper(*args, **kwargs):
                user_id = kwargs.get('user_id', 'unknown')
                try:
                    result = func(*args, **kwargs)
                    self.log_event(event_type, user_id, resource, action, "SUCCESS")
                    return result
                except PermissionError as e:
                    self.log_event(event_type, user_id, resource, action, "DENIED",
                                 details={"error": str(e)})
                    raise
                except Exception as e:
                    self.log_event(event_type, user_id, resource, action, "FAILURE",
                                 details={"error": str(e)})
                    raise
            return wrapper
        return decorator


# Usage
audit = ISO27001AuditLogger("payment-service")

@audit.audit("DATA_ACCESS", "customer_records", "READ")
def get_customer(customer_id: str, user_id: str):
    # ... fetch customer
    pass

# Manual event logging
audit.log_event(
    event_type="AUTHENTICATION",
    user_id="john.doe@company.com",
    resource="web-portal",
    action="LOGIN",
    result="SUCCESS",
    source_ip="203.0.113.45"
)

audit.log_event(
    event_type="AUTHORIZATION",
    user_id="jane.smith@company.com",
    resource="admin-panel",
    action="ACCESS_ATTEMPT",
    result="DENIED",
    source_ip="203.0.113.46",
    details={"reason": "insufficient_permissions", "required_role": "admin"}
)
```

### 8.25 — Secure Development Lifecycle

- Security is integrated into the software development process
- Security testing happens before production
- Developers receive security training

**How DevOps implements it (SSDLC pipeline):**

stages:
  # DESIGN PHASE
  - name: Threat Modeling
    when: "Before sprint starts"

      - Pre-commit hooks (Gitleaks — no secrets in code)

  - name: Change Advisory Board (CAB) Approval

## ISO 27001 Audit Evidence Checklist

```bash
#!/bin/bash
# iso27001-evidence-collector.sh
# Collect evidence for ISO 27001 audit

AUDIT_DATE=$(date +%Y-%m-%d)
EVIDENCE_DIR="iso27001-audit-evidence-$AUDIT_DATE"
mkdir -p "$EVIDENCE_DIR"

echo "Collecting ISO 27001 audit evidence..."

# 8.2 — Privileged Access (who has admin)
echo "Collecting privileged access evidence..."
aws iam get-account-authorization-details \
  --filter LocalManagedPolicy AWSManagedPolicy \
  --output json > "$EVIDENCE_DIR/iam-account-details.json"

# 8.5 — MFA status for all users
echo "Collecting MFA status..."
aws iam generate-credential-report
sleep 5
aws iam get-credential-report \
  --query 'Content' \
  --output text | base64 -d > "$EVIDENCE_DIR/iam-credential-report.csv"

# 8.8 — Vulnerability scan results (last 30 days)
echo "Collecting vulnerability scan results..."
aws securityhub get-findings \
  --filters '{"ComplianceStatus":[{"Value":"FAILED","Comparison":"EQUALS"}],"SeverityLabel":[{"Value":"CRITICAL","Comparison":"EQUALS"}]}' \
  --max-results 100 > "$EVIDENCE_DIR/security-hub-critical-findings.json"

# 8.9 — Config compliance status
echo "Collecting config compliance..."
aws configservice get-compliance-summary-by-config-rule \
  --output json > "$EVIDENCE_DIR/config-compliance-summary.json"

# 8.15 — CloudTrail (last 7 days of security events)
echo "Collecting audit trail..."
aws cloudtrail lookup-events \
  --start-time $(date -d '-7 days' +%Y-%m-%dT%H:%M:%S) \
  --lookup-attributes AttributeKey=EventName,AttributeValue=ConsoleLogin \
  --max-results 200 > "$EVIDENCE_DIR/cloudtrail-logins.json"

# 8.32 — Change management (recent deployments)
echo "Collecting change management evidence..."
aws codedeploy list-deployments \
  --create-time-range start=$(date -d '-30 days' +%Y-%m-%dT%H:%M:%S),end=$(date +%Y-%m-%dT%H:%M:%S) \
  --output json > "$EVIDENCE_DIR/recent-deployments.json"

# Encryption check (8.24)
echo "Checking encryption compliance..."
aws s3api list-buckets --query 'Buckets[*].Name' --output text | \
  tr '\t' '\n' | while read bucket; do
    aws s3api get-bucket-encryption --bucket "$bucket" 2>/dev/null || \
      echo "NOT ENCRYPTED: $bucket"
  done > "$EVIDENCE_DIR/s3-encryption-check.txt"

# Create evidence summary
cat > "$EVIDENCE_DIR/README.md" << EOF
# ISO 27001 Audit Evidence Package
Date: $AUDIT_DATE

## Files
- iam-account-details.json    — Control 8.2 (Privileged Access)
- iam-credential-report.csv   — Control 8.5 (MFA status)
- security-hub-critical-findings.json — Control 8.8 (Vulnerability Management)
- config-compliance-summary.json — Control 8.9 (Configuration Management)
- cloudtrail-logins.json      — Control 8.15 (Logging/Audit Trail)
- recent-deployments.json     — Control 8.32 (Change Management)
- s3-encryption-check.txt     — Control 8.24 (Cryptography)

## Collection Method
Automated via iso27001-evidence-collector.sh
All evidence is tamper-evident (CloudTrail logs the collection itself)
EOF

echo "Evidence package: $EVIDENCE_DIR/"
ls -la "$EVIDENCE_DIR/"
```

## Interview Questions — ISO 27001

**Q: What is the difference between ISO 27001 and SOC 2?**
```
ISO 27001:
  - International standard (global recognition)
  - Certification by accredited auditor
  - Covers ALL information assets (not just cloud)
  - More prescriptive control set (93 controls)

SOC 2:
  - American standard (AICPA)
  - Audit report (not a certification)
  - Focused on cloud service providers
  - 5 trust service criteria (security, availability, confidentiality, privacy, processing integrity)

Most enterprises want BOTH:
  ISO 27001 for global customers
  SOC 2 Type II for US enterprise sales
```

**Q: How does DevOps help achieve ISO 27001 certification?**
```
1. Configuration management (A.8.9) → Terraform, Ansible (all configs in git)
2. Vulnerability management (A.8.8) → Trivy, Checkov in CI/CD pipeline
3. Change management (A.8.32) → Git PRs, approvals, audit trail
4. Logging (A.8.15) → Centralized logging (Loki, CloudWatch)
5. Access control (A.8.2) → RBAC, IRSA, least privilege in code
6. Secure SDLC (A.8.25) → Security scanning in every pipeline
```
